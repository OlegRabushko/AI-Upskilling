Модуль 3

AI-assisted SDLC с coding agents

Здесь вы перестаёте печатать каждую строку сами и начинаете направлять AI-агента: Copilot, Claude Code или Cursor. Вы соберёте каркас сервиса KnowledgeBot (POST /ask), но главное — освоите контролируемый процесс: план → ограниченная область → проверка diff → тесты.

Задания можно выполнять в VS Code с GitHub Copilot или в Claude Code / Cursor. Код сервиса — на FastAPI, но акцент модуля на процессе работы с агентом.

  1. GitHub Copilot в работе
  2. Claude Code и CLAUDE.md
  3. Spec-driven development

Задание 3.1

GitHub Copilot в работе

Что делаем: используем автодополнение и chat для первого эндпойнта. Зачем: понять два режима Copilot — подсказка по ходу набора и диалог по задаче — и где каждый уместен.

Шаг 1Проект и зависимости

mkdir knowledgebot
cd knowledgebot
python -m venv .venv
.venv\Scripts\activate
pip install fastapi uvicorn pytest httpx

Шаг 2Автодополнение по комментарию

Создайте app/main.py, напишите только комментарий и дайте Copilot дополнить тело: 

# FastAPI app with POST /ask that takes {"question": str}
# and returns {"answer": str, "sources": list[str]}
Copilot предложит каркас. Не принимайте вслепую — читайте предложение перед Tab.

Шаг 3Эталон, который должен получиться 

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()

class AskRequest(BaseModel):
    question: str

class AskResponse(BaseModel):
    answer: str
    sources: list[str]

@app.post("/ask", response_model=AskResponse)
def ask(req: AskRequest) -> AskResponse:
    return AskResponse(answer=f"Заглушка: {req.question}", sources=[])

Шаг 4Copilot Chat для теста

В чате Copilot попросите: «Напиши pytest для POST /ask с TestClient». Ожидаемый результат: 

# tests/test_ask.py
from fastapi.testclient import TestClient
from app.main import app

client = TestClient(app)

def test_ask_ok():
    r = client.post("/ask", json={"question": "привет"})
    assert r.status_code == 200
    assert "answer" in r.json()

Шаг 5Запуск

uvicorn app.main:app --reload
# в другом терминале:
pytest -q
Вывод: автодополнение ускоряет набор, chat решает задачу целиком. Ответственность за корректность — на вас.
Задание 3.2

Claude Code и память проекта (CLAUDE.md)

Что делаем: даём агенту постоянные правила через CLAUDE.md и работаем в режиме плана. Зачем: чтобы агент соблюдал конвенции без повторов и не менял лишнего.

Шаг 1Создаём CLAUDE.md

# KnowledgeBot

## Стек
- Python 3.12, FastAPI, pytest

## Правила для агента
- Меняй только файлы, которые я явно назвал.
- Не рефактори работающий код без запроса.
- Всегда добавляй тесты для нового кода.
- Используй type hints.
- Перед коммитом запускай pytest.

Шаг 2Первый коммит — правила, не код 

git init
git add CLAUDE.md
git commit -m "chore: add CLAUDE.md"

Шаг 3Режим плана

Промпт агенту:
"Plan: предложи структуру проекта KnowledgeBot по спецификации.
Файлы пока не создавай — покажи план."
Стоимость плохого плана — ноль. Стоимость плохого исполнения — грязный diff. Сначала план.

Шаг 4Ограниченная реализация 

Промпт:
"Создай ТОЛЬКО app/main.py с эндпойнтом POST /ask (заглушка) и
tests/test_ask.py. Другие файлы не трогай."

Шаг 5Проверка памяти

Закройте и снова откройте агента в папке проекта, спросите:
"Какие у тебя правила по этому проекту?"
Агент должен пересказать содержимое CLAUDE.md.
Вывод: CLAUDE.md — постоянная память проекта; правила задаются один раз и применяются в каждой сессии.
Задание 3.3

Spec-driven development

Что делаем: сначала пишем спецификацию, затем агент реализует по ней. Зачем: чёткая спека = предсказуемый код и готовые критерии приёмки.

Шаг 1Пишем спецификацию

# spec/ask-endpoint.md
## Фича: POST /ask
Вход:  {"question": string, непустая}
Выход: {"answer": string, "sources": string[]}
Правила:
- Пустой вопрос -> HTTP 422.
- Длина вопроса <= 500 символов.
- sources пока всегда [].
Критерии приёмки:
- Тест на успешный ответ.
- Тест на пустой вопрос (422).
- Тест на слишком длинный вопрос (422).

Шаг 2Агент строит план по спеке 

Промпт:
"Прочитай spec/ask-endpoint.md. Plan: какие файлы и тесты нужны,
чтобы выполнить все критерии приёмки? Код не пиши."

Шаг 3Реализация валидации

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI()

class AskRequest(BaseModel):
    question: str = Field(min_length=1, max_length=500)

class AskResponse(BaseModel):
    answer: str
    sources: list[str]

@app.post("/ask", response_model=AskResponse)
def ask(req: AskRequest) -> AskResponse:
    return AskResponse(answer=f"Заглушка: {req.question}", sources=[])

Шаг 4Тесты по критериям приёмки 

from fastapi.testclient import TestClient
from app.main import app
client = TestClient(app)

def test_ok():
    assert client.post("/ask", json={"question": "привет"}).status_code == 200

def test_empty():
    assert client.post("/ask", json={"question": ""}).status_code == 422

def test_too_long():
    assert client.post("/ask", json={"question": "x" * 501}).status_code == 422

Шаг 5Приёмка

pytest -q
# все три теста должны пройти — спецификация выполнена
Вывод: спека даёт агенту цель и одновременно критерии проверки. Код «готов», когда зелёные тесты по приёмке.
Задание 3.4

Проверка вывода агента

Что делаем: намеренно ловим ошибку в коде агента. Зачем: AI-код выглядит правильным чаще, чем является им; чтение diff — обязательный навык.

Шаг 1Просим нетривиальную функцию 

Промпт агенту:
"Реализуй функцию paginate(items, page, per_page), которая
возвращает срез страницы. Страницы нумеруются с 1."

Шаг 2Типичный ответ агента (с багом) 

def paginate(items, page, per_page):
    start = page * per_page          # БАГ: при page=1 пропускает первую страницу
    end = start + per_page
    return items[start:end]

Шаг 3Читаем diff и находим ошибку 

git diff
# Вопрос к себе: при page=1 и per_page=10 start=10 -> это уже вторая страница.
# Off-by-one: нумерация с 1 не учтена.

Шаг 4Исправляем и покрываем тестом 

def paginate(items, page, per_page):
    start = (page - 1) * per_page    # исправлено
    return items[start:start + per_page]

def test_first_page():
    assert paginate(list(range(30)), 1, 10) == list(range(0, 10))
def test_second_page():
    assert paginate(list(range(30)), 2, 10) == list(range(10, 20))

Шаг 5Дисциплина коммитов

git add -A
git commit -m "fix: off-by-one in paginate, add tests"
Вывод: коммитьте до сессии агента, читайте весь diff, запускайте тесты сами — не доверяйте фразе «готово».
Задание 3.5

Свои команды и structured vibe coding

Что делаем: оформляем повторяемый промпт в команду /review. Зачем: то, что вы печатаете чаще двух раз, должно стать переиспользуемой командой для всей команды.

Шаг 1Создаём команду

# .claude/commands/review.md
Проверь последние изменения. Найди:
- отсутствующие или неполные тесты;
- забытые print/console.log;
- захардкоженные значения вместо переменных окружения;
- функции длиннее 30 строк;
- отсутствие валидации на новых эндпойнтах.
Выведи нумерованный список, пометь [MUST FIX] / [SHOULD FIX] / [SUGGESTION].

Шаг 2Запускаем

/review

Шаг 3Уточняем под себя

Если вывод слишком общий — добавьте в команду:
"Игнорируй тестовые файлы и комментарии. Указывай файл и строку."

Шаг 4Structured vibe coding — цикл 

Повторяемый цикл для каждой фичи:
1. Спека (3.3)       -> что строим и критерии
2. Plan              -> агент показывает план
3. Ограниченная область -> только нужные файлы
4. /review           -> своя проверка
5. Тесты + diff      -> ручная верификация
6. Commit            -> атомарный коммит

Шаг 5Фиксируем workflow

# WORKFLOW.md
Каждая фича проходит цикл: spec -> plan -> scoped edit -> /review -> tests -> commit.
Первый коммит проекта — CLAUDE.md, не исходный код.
Итог модуля: у вас есть каркас сервиса и, что важнее, воспроизводимый процесс работы с агентом. В модуле 4 научимся измерять качество его ответов.
