Модуль 4

Evals и tracing

«Кажется, отвечает неплохо» — это не метрика. В этом модуле вы построите набор проверочных вопросов, посчитаете объективные метрики, подключите LLM-судью и добавите трассировку, чтобы видеть путь каждого запроса.

Используем KnowledgeBot из модулей 1–3. Для LLM-судьи — llm_client.py.

Задания модуля

  1. Набор проверочных вопросов
  2. Метрики качества
  3. LLM-as-a-Judge
  4. Трассировка запроса
  5. Observability
Задание 4.1

Набор проверочных вопросов

Что делаем: создаём датасет вопросов с эталонными ответами. Зачем: один удачный ответ ничего не доказывает — нужен стабильный набор, на котором можно сравнивать версии.

Шаг 1Файл с эталонами

# evals.jsonl — по одному JSON на строку
{"id": "q1", "question": "Сколько дней отпуска?", "expected": "28", "sources": ["vacation.md"]}
{"id": "q2", "question": "Как сбросить пароль?", "expected": "письмо", "sources": ["account.md"]}
{"id": "q3", "question": "Что делать при двойном списании?", "expected": "биллинг", "sources": ["billing.md"]}
{"id": "q4", "question": "Какая погода на Марсе?", "expected": "не найдено", "sources": []}

Шаг 2Загрузка датасета

import json

def load_evals(path: str = "evals.jsonl") -> list[dict]:
    with open(path, encoding="utf-8") as f:
        return [json.loads(line) for line in f if line.strip()]

cases = load_evals()
print(f"Загружено кейсов: {len(cases)}")

Шаг 3Заглушка бота для прогона 

# пока бот простой; в модуле 5 он станет RAG-ботом
def bot(question: str) -> dict:
    data = {"отпуск": ("28 дней", ["vacation.md"]),
            "пароль": ("Сбросьте по ссылке из письма", ["account.md"]),
            "списан": ("Обратитесь в биллинг", ["billing.md"])}
    for key, (ans, src) in data.items():
        if key in question.lower():
            return {"answer": ans, "sources": src}
    return {"answer": "Информация не найдена", "sources": []}

Шаг 4Прогон по всем вопросам 

def run(cases: list[dict]) -> list[dict]:
    results = []
    for c in cases:
        out = bot(c["question"])
        results.append({**c, "got": out["answer"], "got_sources": out["sources"]})
    return results

results = run(cases)
for r in results:
    print(r["id"], "->", r["got"])

Шаг 5Почему важен кейс-отказ 

# q4 проверяет, что бот НЕ выдумывает ответ про Марс.
# Без таких кейсов вы не заметите галлюцинации.
mars = [r for r in results if r["id"] == "q4"][0]
print("Отказ сработал:", "не найден" in mars["got"].lower())
Вывод: датасет включает не только «есть ответ», но и «ответа быть не должно».
Задание 4.2

Метрики качества

Что делаем: считаем correctness, точность источников и формат. Зачем: метрики превращают «ощущения» в числа, которые можно отслеживать между релизами.

Шаг 1Корректность ответа

def is_correct(expected: str, got: str) -> bool:
    return expected.lower() in got.lower()   # простая проверка вхождения

Шаг 2Точность источников

def source_ok(expected: list[str], got: list[str]) -> bool:
    if not expected:
        return got == []            # для отказа источников быть не должно
    return any(s in got for s in expected)

Шаг 3Сводные метрики

def score(results: list[dict]) -> dict:
    n = len(results)
    correct = sum(is_correct(r["expected"], r["got"]) for r in results)
    src = sum(source_ok(r["sources"], r["got_sources"]) for r in results)
    return {
        "correctness": round(correct / n, 2),
        "source_accuracy": round(src / n, 2),
        "n": n,
    }

print(score(results))

Шаг 4Отчёт по кейсам

print(f'{"id":4}{"correct":9}{"src":5}')
for r in results:
    print(f'{r["id"]:4}{str(is_correct(r["expected"], r["got"])):9}'
          f'{str(source_ok(r["sources"], r["got_sources"])):5}')

Шаг 5Порог регрессии

THRESHOLD = 0.75
m = score(results)
assert m["correctness"] >= THRESHOLD, f"Качество упало: {m['correctness']}"
print("Прошли порог качества.")
Вывод: метрики + порог = защита от регрессий. Такой assert можно поставить в CI.
Задание 4.3

LLM-as-a-Judge

Что делаем: просим отдельную модель оценить ответ по шкале 1–5. Зачем: проверка вхождением груба; судья-модель оценивает смысл, но ей тоже нельзя доверять слепо.

Шаг 1Prompt судьи

JUDGE = """Ты строгий оценщик ответов поддержки.
Дай оценку от 1 до 5, где 5 — точный и полезный ответ.
Верни ТОЛЬКО JSON: {"score": int, "reason": str}.
Вопрос: {q}
Эталон: {exp}
Ответ бота: {got}"""

Шаг 2Вызов судьи

import json
from llm_client import LLMClient
judge_model = LLMClient()

def judge(q: str, expected: str, got: str) -> dict:
    prompt = JUDGE.format(q=q, exp=expected, got=got)
    raw = judge_model.ask(prompt, response_format={"type": "json_object"})
    return json.loads(raw)

Шаг 3Оцениваем прогон

for r in results:
    verdict = judge(r["question"], r["expected"], r["got"])
    r["judge"] = verdict["score"]
    print(r["id"], verdict["score"], "-", verdict["reason"][:50])

Шаг 4Сверяем судью с эталоном 

# Где судья и простая метрика расходятся — там интересные случаи
for r in results:
    rule = is_correct(r["expected"], r["got"])
    llm = r["judge"] >= 4
    if rule != llm:
        print("Расхождение:", r["id"], "rule=", rule, "judge=", r["judge"])

Шаг 5Средняя оценка судьи

avg = sum(r["judge"] for r in results) / len(results)
print(f"Средняя оценка судьи: {avg:.2f} / 5")
Вывод: LLM-судья масштабирует оценку смысла, но сам может ошибаться — держите небольшой «золотой» набор, проверенный человеком.
Задание 4.4

Трассировка запроса (tracing)

Что делаем: присваиваем каждому запросу trace_id и логируем все шаги. Зачем: когда ответ плохой, нужно видеть весь путь: какой контекст, какие токены, сколько времени.

Шаг 1Идентификатор трассы

import uuid, time

def new_trace() -> str:
    return uuid.uuid4().hex[:8]

Шаг 2Логгер шагов

TRACES: list[dict] = []

def log_step(trace_id: str, step: str, **data):
    TRACES.append({"trace": trace_id, "step": step, "ts": time.time(), **data})

Шаг 3Оборачиваем бота

def traced_bot(question: str) -> dict:
    tid = new_trace()
    log_step(tid, "received", question=question)
    start = time.time()
    out = bot(question)                       # bot() из задания 4.1
    log_step(tid, "answered",
             latency=round(time.time() - start, 3),
             sources=out["sources"])
    out["trace"] = tid
    return out

print(traced_bot("Сколько дней отпуска?"))

Шаг 4Смотрим одну трассу целиком 

def show_trace(trace_id: str):
    for e in TRACES:
        if e["trace"] == trace_id:
            print(e["step"], {k: v for k, v in e.items() if k not in ("trace", "ts")})

last = TRACES[-1]["trace"]
show_trace(last)

Шаг 5Находим медленные запросы 

slow = [e for e in TRACES if e["step"] == "answered" and e.get("latency", 0) > 1.0]
print("Медленных запросов:", len(slow))
Вывод: trace_id связывает все события одного запроса — это основа отладки в проде.
Задание 4.5

Observability

Что делаем: собираем агрегаты по всем запросам и сохраняем в файл. Зачем: мониторинг показывает здоровье системы во времени, а не только один ответ.

Шаг 1Копим метрики запросов

import json, time

METRICS: list[dict] = []

def record(trace_id: str, latency: float, tokens: int, error: bool):
    METRICS.append({"trace": trace_id, "latency": latency,
                    "tokens": tokens, "error": error, "ts": time.time()})

Шаг 2Наполняем демо-данными

import random
for _ in range(50):
    record(uuid.uuid4().hex[:8],
           latency=round(random.uniform(0.3, 2.5), 2),
           tokens=random.randint(200, 1500),
           error=random.random() < 0.1)

Шаг 3Сводный дашборд в консоль 

def dashboard(m: list[dict]):
    n = len(m)
    avg_lat = sum(x["latency"] for x in m) / n
    p95 = sorted(x["latency"] for x in m)[int(n * 0.95)]
    err = sum(x["error"] for x in m) / n
    tok = sum(x["tokens"] for x in m)
    print(f"Запросов:    {n}")
    print(f"Средн. лат.: {avg_lat:.2f}s")
    print(f"P95 лат.:    {p95:.2f}s")
    print(f"Ошибки:      {err:.1%}")
    print(f"Токены всего:{tok}")

dashboard(METRICS)

Шаг 4Алерт по порогам

def check_alerts(m: list[dict]):
    err = sum(x["error"] for x in m) / len(m)
    if err > 0.05:
        print(f"ALERT: доля ошибок {err:.1%} выше 5%")

check_alerts(METRICS)

Шаг 5Экспорт для анализа

with open("metrics.json", "w", encoding="utf-8") as f:
    json.dump(METRICS, f, ensure_ascii=False, indent=2)
print("Метрики сохранены в metrics.json")
Итог модуля: вы умеете измерять качество (evals), оценивать смысл (LLM-судья) и наблюдать систему (tracing + метрики). В модуле 5 бот наконец получит настоящие знания через RAG.
