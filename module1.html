Модуль 1

Основы: модели, токены и стоимость

Цель модуля — перестать воспринимать LLM как «магию» и увидеть механику: модель предсказывает следующий токен, за каждый токен вы платите, у каждой модели свои пределы и цена. В конце вы соберёте переиспользуемый API-клиент, который станет фундаментом проекта KnowledgeBot.

Единый стек курса: Python 3.12+, пакет openai (совместим с OpenAI и многими провайдерами), tiktoken для подсчёта токенов. Локальная альтернатива без оплаты — модель через Ollama.

Задание 1.1

Как работают языковые модели

Что делаем: демонстрацию предсказания следующего токена. Зачем: чтобы на практике увидеть, что модель не «думает» целыми фразами, а на каждом шаге выбирает следующий токен из распределения вероятностей. Это объясняет и галлюцинации, и влияние температуры.

Шаг 2Самый простой запрос

from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()
client = OpenAI()

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Небо обычно какого цвета днём?"}],
)
print(resp.choices[0].message.content)

Шаг 3Показать кандидатов следующего токена

Расширяем запрос: просим вернуть вероятности и генерируем только 1 токен. 

resp = client.chat.completions.create(
    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Небо обычно"}],
    max_tokens=1,
    logprobs=True,
    top_logprobs=5,   # топ-5 вариантов следующего токена
)

import math
top = resp.choices[0].logprobs.content[0].top_logprobs
for cand in top:
    prob = math.exp(cand.logprob)          # из logprob в вероятность 0..1
    print(f"{cand.token!r:15} {prob:6.1%}")
Вы увидите несколько вариантов с процентами, например ' голубого' — 72%, ' синего' — 11%. Это и есть «распределение вероятностей следующего токена».

Шаг 4Генерация токен за токеном вручную

Собираем ответ по одному токену, подавая предыдущий результат обратно — так работает модель внутри. 

prompt = "Небо обычно"
text = prompt
for _ in range(6):
    r = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": text}],
        max_tokens=1,
    )
    next_token = r.choices[0].message.content
    text += next_token
    print(text)   # видно, как фраза растёт по одному кусочку

Шаг 5Эффект температуры

for temp in (0.0, 1.3):
    r = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "Придумай название для кофейни"}],
        temperature=temp,
    )
    print(temp, "->", r.choices[0].message.content)
Вывод задания: при temperature=0 модель почти всегда берёт самый вероятный токен (ответы стабильны), при высокой температуре — выбирает менее вероятные (ответы разнообразнее, но менее предсказуемы).
Задание 1.2

Токены, контекстное окно и стоимость

Что делаем: счётчик токенов и калькулятор стоимости. Зачем: вы платите за токены ввода и вывода, а контекст конечен. Нужно уметь измерять то, за что платите.

Шаг 1Считаем токены

import tiktoken

enc = tiktoken.get_encoding("o200k_base")  # кодировка новых моделей OpenAI

def count_tokens(text: str) -> int:
    return len(enc.encode(text))

print(count_tokens("Привет"))               # короткое слово
print(count_tokens("Привет, как дела?"))    # больше токенов
Токен — это не буква и не слово, а кусочек текста. Русский текст обычно «дороже» по токенам, чем английский: полезно увидеть это своими глазами.

Шаг 2Короткий и длинный контекст 

short = "Сделай краткое резюме."
long = short + " " + ("Это тестовое предложение. " * 300)

print("short:", count_tokens(short))
print("long: ", count_tokens(long))

Шаг 3Калькулятор стоимости

# Цены за 1000 токенов — ПРИМЕР. Подставьте актуальные из тарифов провайдера.
PRICES = {
    "gpt-4o-mini": {"in": 0.00015, "out": 0.00060},
    "gpt-4o":      {"in": 0.00250, "out": 0.01000},
}

def estimate_cost(model: str, in_tokens: int, out_tokens: int) -> float:
    p = PRICES[model]
    return in_tokens / 1000 * p["in"] + out_tokens / 1000 * p["out"]

print(estimate_cost("gpt-4o-mini", 1500, 300))
print(estimate_cost("gpt-4o", 1500, 300))

Шаг 4Реальные токены из ответа API

Шаг 5Подходим к пределу контекста 

CONTEXT_LIMIT = 128_000   # пример окна модели

def fits(text: str) -> bool:
    used = count_tokens(text)
    print(f"{used} / {CONTEXT_LIMIT} токенов ({used / CONTEXT_LIMIT:.1%})")
    return used < CONTEXT_LIMIT

fits(long)
fits("Это предложение. " * 20000)   # уже близко к пределу
Вывод задания: всё, что вы отправляете (инструкция + история + документы), занимает место в контексте и стоит денег. Отсюда вытекает модуль про оптимизацию.
Задание 1.3

Различия между моделями и провайдерами

Что делаем: прогоняем одинаковые вопросы через несколько моделей и сравниваем. Зачем: «самая мощная модель» не всегда нужна — на простой задаче дешёвая отвечает не хуже, но в разы дешевле.

Шаг 1Единая обёртка вызова

import time
from openai import OpenAI
client = OpenAI()

def ask(model: str, prompt: str) -> dict:
    start = time.time()
    r = client.chat.completions.create(
        model=model,
        messages=[{"role": "user", "content": prompt}],
    )
    return {
        "model": model,
        "answer": r.choices[0].message.content,
        "in": r.usage.prompt_tokens,
        "out": r.usage.completion_tokens,
        "sec": round(time.time() - start, 2),
    }

Шаг 2Батарея вопросов

prompts = {
    "простой":  "Столица Японии?",
    "рассуждение": "У Ани 3 яблока, она отдала 1 и купила 4. Сколько стало?",
    "код": "Напиши на Python функцию is_even(n).",
}
models = ["gpt-4o-mini", "gpt-4o"]

rows = []
for label, p in prompts.items():
    for m in models:
        res = ask(m, p)
        res["label"] = label
        rows.append(res)

Шаг 3Таблица сравнения + стоимость 

# переиспользуем estimate_cost и PRICES из задания 1.2
for r in rows:
    r["cost"] = round(estimate_cost(r["model"], r["in"], r["out"]), 6)

print(f'{"задача":12}{"модель":14}{"ток.in":>7}{"ток.out":>8}{"сек":>6}{"$":>10}')
for r in rows:
    print(f'{r["label"]:12}{r["model"]:14}{r["in"]:7}{r["out"]:8}{r["sec"]:6}{r["cost"]:10}')

Шаг 4Другой провайдер / локальная модель

Та же обёртка работает с OpenAI-совместимым endpoint (например, локальный Ollama) — меняется только базовый URL и ключ: 

local = OpenAI(base_url="http://localhost:11434/v1", api_key="ollama")

def ask_local(model: str, prompt: str) -> dict:
    r = local.chat.completions.create(
        model=model,  # напр. "llama3.1"
        messages=[{"role": "user", "content": prompt}],
    )
    return {"model": model, "answer": r.choices[0].message.content}

Задание 1.4

Оптимизация расходов и объёма контекста

Что делаем: берём «дорогой» запрос и последовательно удешевляем его, не теряя качества. Зачем: это ежедневный навык при работе с AI-агентами, где контекст быстро раздувается.

Шаг 1Базовая (расточительная) версия 

document = open("big_policy.txt", encoding="utf-8").read()  # большой документ

def answer_naive(question: str) -> dict:
    prompt = f"Документ:\n{document}\n\nВопрос: {question}"
    return ask("gpt-4o-mini", prompt)   # ask() из задания 1.3

res = answer_naive("Сколько дней отпуска?")
print(res["in"], "входных токенов")     # очень много

Шаг 2Приём 1 — отдавать только нужный фрагмент 

def relevant_section(doc: str, keyword: str) -> str:
    # простейший поиск абзаца по ключевому слову (полноценный поиск — в модуле 5)
    for para in doc.split("\n\n"):
        if keyword.lower() in para.lower():
            return para
    return doc[:500]

def answer_scoped(question: str, keyword: str) -> dict:
    chunk = relevant_section(document, keyword)
    prompt = f"Фрагмент:\n{chunk}\n\nВопрос: {question}"
    return ask("gpt-4o-mini", prompt)

res2 = answer_scoped("Сколько дней отпуска?", "отпуск")
print(res2["in"], "входных токенов")     # в десятки раз меньше

Шаг 3Приём 2 — сжимать историю диалога 

def summarize(history: str) -> str:
    r = ask("gpt-4o-mini", f"Сожми до 3 пунктов ключевые решения:\n{history}")
    return r["answer"]

long_history = "... длинная переписка на два часа ..."
handoff = summarize(long_history)   # короткая выжимка вместо всей истории

Шаг 4Приём 3 — ограничивать вывод

    model="gpt-4o-mini",
    messages=[{"role": "user", "content": "Ответь одним словом: столица Италии?"}],

rows = [

Задание 1.5

Использование LLM через API

Что делаем: оборачиваем всё в переиспользуемый клиент LLMClient. Зачем: это основа KnowledgeBot — все следующие модули будут импортировать именно его.

Шаг 1Класс-обёртка

# файл: llm_client.py
import time
from openai import OpenAI
from dotenv import load_dotenv

load_dotenv()

class LLMClient:
    def __init__(self, model: str = "gpt-4o-mini", base_url: str | None = None):
        self.model = model
        self.client = OpenAI(base_url=base_url) if base_url else OpenAI()

    def ask(self, prompt: str, system: str | None = None, **kwargs) -> str:
        messages = []
        if system:
            messages.append({"role": "system", "content": system})
        messages.append({"role": "user", "content": prompt})
        r = self.client.chat.completions.create(
            model=self.model, messages=messages, **kwargs
        )
        return r.choices[0].message.content

Шаг 2Базовый retry и таймаут 

    def ask_safe(self, prompt: str, retries: int = 3, **kwargs) -> str:
        for attempt in range(retries):
            try:
                return self.ask(prompt, timeout=20, **kwargs)
            except Exception as e:
                if attempt == retries - 1:
                    return f"[Ошибка после {retries} попыток: {e}]"
                time.sleep(1.5 * (attempt + 1))   # нарастающая пауза
Добавьте этот метод внутрь класса LLMClient (с тем же отступом, что и ask).

Шаг 3Системный prompt и параметры

Шаг 4Потоковый ответ (streaming) 

    def stream(self, prompt: str):
        stream = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
            stream=True,
        )
        for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                print(delta, end="", flush=True)
